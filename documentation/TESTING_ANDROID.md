# Тест на телефон с Android (APK + ngrok)

API-то върви на твоя компютър, ngrok го прави достъпно от интернет, а
тестовото APK на телефона говори с ngrok адреса. Адресът се въвежда в
самото приложение, затова едно APK работи с всеки нов ngrok адрес.

```
 телефон (APK) ──https──▶ ngrok ──▶ твоят Mac :3000 (API) ──▶ Postgres + Redis (Docker)
```

## 1. Еднократна подготовка на Mac

```bash
brew install node@22 pnpm ngrok
```

- Инсталирай **Docker Desktop** и го стартирай.
- Направи безплатен акаунт на ngrok.com и свържи токена:
  ```bash
  ngrok config add-authtoken <твоят-token>
  ```

## 2. Стартиране на сървъра

```bash
./scripts/dev-tunnel.sh
```

Скриптът вдига Postgres и Redis, прилага миграциите, създава админ акаунт
със **случайна парола** (записана в `.dev-credentials`, файлът не влиза в
git), стартира API-то и ngrok. Накрая отпечатва:

```
  Server address for the phone:  https://xxxx.ngrok-free.app
```

Варианти:
- `NO_TUNNEL=1 ./scripts/dev-tunnel.sh`: без ngrok, ако телефонът е в
  същата Wi-Fi мрежа (ползва се `http://<IP-на-Mac>:3000`).
- `USE_LOCAL_SERVICES=1`: ако Postgres/PostGIS и Redis вече вървят без Docker.

> ⚠️ Докато ngrok е включен, API-то е публично в интернет. Затова скриптът
> никога не ползва паролата по подразбиране от кода. Спирай с Ctrl+C,
> когато приключиш.

## 3. Построяване на APK

**Вариант А: EAS Build (в облака, без Android Studio)**

```bash
npm install -g eas-cli
```

```bash
cd apps/mobile && eas login && eas build -p android --profile preview
```

След 10–20 минути EAS дава линк за сваляне на `.apk`. Профилът `preview`
(в `apps/mobile/eas.json`) включва полето за смяна на сървъра. Профилът
`production` го изключва.

**Вариант Б: локално с Android Studio**

```bash
cd apps/mobile && EXPO_PUBLIC_ALLOW_SERVER_OVERRIDE=1 npx expo run:android --variant release
```

## 4. Инсталиране и свързване

1. Свали APK-то на телефона и разреши „инсталиране от неизвестни източници“.
2. Отвори приложението. Най-долу на екрана за вход натисни **⚙︎ Сървър**.
3. Постави ngrok адреса и натисни **Запази и провери**. Трябва да видиш
   „✓ Сървърът отговаря“.

## 5. Тестов сценарий

1. Отвори админ таблото (`cd apps/admin && pnpm dev`, после
   http://localhost:3001) с данните от `.dev-credentials`.
2. **Invitations** → създай покана за пътник и препиши кода.
3. В приложението: **Регистрация с покана** → въведи кода.
4. В таблото: **Members** → **Approve**.
5. Влез в приложението. В **Профил** добави тестова карта, после поръчай
   курс от **Начало**.
6. За шофьорската страна ти трябва втори телефон (или емулатор) с акаунт,
   поканен като DRIVER и одобрен в **Drivers**.

## Известни ограничения на тестовия билд

- Картата е placeholder. Реалната карта (react-native-maps) изисква API
  ключ за Google Maps.
- Дестинацията е фиксирано отместване от текущата позиция, докато не се
  включи доставчик за търсене на адреси.
- GPS на шофьора работи само докато приложението е на преден план.
- Плащанията са в **тестов режим** (sandbox) и не се движат реални пари.
- Безплатният ngrok адрес се сменя при всеки рестарт. Въведи новия в ⚙︎ Сървър.

## Отстраняване на проблеми

| Симптом | Причина |
|---|---|
| „Няма връзка със сървъра“ | API-то или ngrok не вървят, или адресът е стар |
| „Сървърът върна неочакван отговор“ | ngrok е спрян (връща HTML вместо JSON) |
| `ngrok did not start` | липсва `ngrok config add-authtoken` |
| Входът с админ паролата не става | `.dev-credentials` е създаден след първия seed; изтрий Docker volume-а (`docker compose -f docker/docker-compose.yml down -v`) и пусни отново |
